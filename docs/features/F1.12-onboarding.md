# F1.12 — Onboarding "Welcome" screen

**Sources:** PRD F1-FR4 (P0), PRD screen S2, Stitch screen 16 ([16-welcome.png](../ui/stitch/16-welcome.png)), DB Design §4.2, API Design §13.1.

## What the user sees

A first-time user (no videos yet, onboarding not done) who reaches the Library is sent once to **/welcome**. People who were already creating before onboarding existed are not interrupted:

1. Three cards: **01 Idea** (type a topic or paste notes) · **02 Storyboard** (review script + scenes, change anything by chatting) · **03 Video** (voiceover, synced animation, post to Instagram).
2. **Which language will most of your videos be in?** — English / हिंदी (Hindi), required, preselected from the profile (English by default).
3. **What do you teach or create about?** — optional, up to 200 characters (e.g. "Class 9 science, personal finance, history"). Used later to tailor idea suggestions (F2.2).
4. A note: the time zone (Asia/Kolkata by default) can be changed in Settings.
5. **Start creating →** saves the language and the answer and marks onboarding done. **Skip** only marks it done. Both go to the Library.

The display name is not asked: it comes from sign-up (or Google) and can be changed in Settings. Instagram is not offered here until M6.

## Data and API

| Change | Where |
|---|---|
| New optional profile field `about: string \| null` (≤ 200 characters, trimmed; empty → null) | DB Design §4.2, `profiles` |
| `onboardingCompletedAt` is set when onboarding is completed or skipped | existing field |
| `PATCH /api/v1/me/profile` also accepts `about` and `onboardingCompleted: true` (only `true`: onboarding can't be undone) | API Design §13.1 |
| The `Profile` resource gains `about` | API Design §12 |

No migration: the field is optional and the app validates it (the `profiles` validator doesn't restrict extra fields).

## Rules

- Only the Library redirects to /welcome, so deep links to a project or Settings are never interrupted. The check runs in the proxy (`needsWelcome` in `server/onboarding.ts`), so the redirect happens before the Library renders anything; the Library page repeats it as a fallback.
- Only users with no projects yet (deleted ones count) are sent there; existing creators skip it. The check runs before the Library queries.
- `onboardingCompletedAt` records the first completion only; sending `onboardingCompleted: true` again keeps it.
- The 200-character limit counts characters (an emoji is one) in the API and in both forms (`lib/profile-limits.ts`).
- /welcome sends users who have already finished onboarding to the Library.
- Signed-out visitors to /welcome go to sign-in (proxy), like the other app pages.
