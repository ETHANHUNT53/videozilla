## How it's built

- **Components:** `ProjectView` places the two columns; `IdeaStep` splits into the **left workspace** (tabs, inputs, idea cards) and the **right brief column** (brief card + chat + bottom card) with the state they share (the brief, the AI runner, the highlights, the editor) staying in one place, so no behaviour moves between owners. The settings panel moves under the brief.
- **Look:** existing tokens and components (`Card`, `Button`, `Chip`, `Eyebrow`, `inputStyles`); new small pieces: a `SegmentedControl` (radio group, keyboard arrows) and `Tag` (mono `[tag]`). No new colours.
- **Responsive:** one column below `lg`; the right column follows the left. 360 px is checked, as before.
- **Accessibility:** the segmented controls are radio groups; the stepper keeps `aria-current="step"`; "Selected" is in text, not colour alone; focus order follows the visual order.
- **Q4, the selected card:** the idea session remembers which card the brief came from (`briefCardId`, set when **Use this** makes the brief; cleared when a brief comes from the idea, the notes, or a new card; kept by chat, edits, Regenerate and angle switches since it's still that card's brief). It's added to the `IdeaSession` resource. No migration.

## Built (2026-10-20)

As designed and answered, with these details:

- **Layout:** `IdeaStep` keeps all its state (autosave, the brief, the AI runner, highlights, the editor) and now renders both columns; the settings panel is passed in as a slot, so no behaviour changed owner. Other steps keep their placeholder + settings layout.
- **Settings** (`components/settings-panel.tsx`): segmented English / हिंदी and ~60s / ~90s (`components/segmented.tsx`: radio groups with arrow keys), selects for audience and board, voice as two radio cards, captions, the read-only "Midnight" style chip. Each change shows at once and is saved with `If-Match`; one change at a time (the controls wait while it saves); a failure puts the old value back; another tab's change (412) loads the latest settings and says the change wasn't saved. "Saving… / Saved ✓" sits by the heading. The "Regenerate brief in Hindi?" bar appears above the brief as soon as the language or length is saved.
- **Ideas:** the topic input with **Suggest ideas** beside it (Enter still asks); "// N ideas"; key points as `[tags]`; **More like this** quiet, **Use this** a button (primary on the Selected card); **Suggest 5 more** as a pill.
- **Brief card:** "// brief" with a green "● ready", **Edit**, the title, each field under a mono label, key points with cyan bullets, "// other angles" stacked for the narrow column, then the chat under "// refine with ai" (bubbles: yours plain, the AI's violet with "// ai"; a one-line box with a send arrow; the 1,000 count appears from 800). With no brief yet, a placeholder card says where it will appear.
- **Header and stepper:** **Next: Storyboard →** (disabled, "// next milestone"); the steps with a number square, label, hint and status dot.
- **Generate card:** "● Brief ready · N key points" (or "No brief yet") with **Generate storyboard →**, disabled until F3.
- **`briefCardId`:** stored on the idea session and in the `IdeaSession` resource (API Design §12, DB Design §4.4).
- **Tests (7 new layout tests + 1 `briefCardId` test, 757 in total; no AI keys):** `components/idea-studio-layout.test.ts` (the column order, which is also the phone order; Next / Generate disabled; one Selected card, in words; the radio groups; the brief's labels and Edit; the empty state; the topic row and pill), `brief.test.ts` (`briefCardId` set by Use this, kept by an angle switch, cleared by an idea brief). The whole earlier suite (F2.1–F2.8 behaviour) passes unchanged.
- **Not checked in a browser here:** a dev server that isn't this session's runs in this folder and Next.js allows one per folder; an isolated copy would need the local database settings and secrets copied out of `.env.local`. QA should check it in mock mode at desktop width and 360 px (and take the before / after screenshots).
