# F2.1 — Idea autosave

**Sources:** [M2 design §3](../M2_DESIGN.md), PRD F2-FR1 / F2-FR9 / F10-FR1, API Design §8 / §13.3, DB Design §4.4 / §7.1.

## What it does

The project page's Idea step now has the three ways to start: **Find a topic**, **I have an idea** and **Use my notes**.
- Each mode keeps its own text, and everything saves by itself.
- The AI buttons are shown disabled until F2.2–F2.4.

## API

| Method | Path | Answer |
|---|---|---|
| `GET` | `/api/v1/projects/{id}/idea` | `200 IdeaSession` + `ETag: "<rev>"` |
| `PUT` | `/api/v1/projects/{id}/idea` | body `{ mode, topicInput?, ideaInput?, notesText? }` → `200 IdeaSession` + new `ETag` |

**Body:**
- strict: unknown fields such as `brief`, `rev` or `userId` → `400`;
- inputs left out stay as they are;
- strings are trimmed and NFC-normalised.

**Limits:**
- 200 / 500 / 20,000 characters, counted as code points like the database (a Hindi letter or an emoji is one);
- bodies up to 128 KB (`413` above).

**`If-Match`:**
- the right rev saves;
- a stale rev → `412 PRECONDITION_FAILED` with the current idea in `details[0].current`;
- missing or `*` → last write wins.

**Behaviour:**
- **No-op save:** sending what's already stored returns `200` with the same rev (no write, no conflict).
- **Status:** only while the project allows `edit_idea` (`idea_draft`, `storyboard_ready`); otherwise `409 INVALID_STATE`.
- **One transaction:** the idea's `rev` goes up and the project's `updatedAt` moves (the video comes first in the Library; the project's own `rev` doesn't change). A concurrent status change conflicts with the save instead of slipping past the check.
- **Someone else's, deleted or unknown project:** `404`, exactly like an unknown id (cross-user suite).

## Autosave in the browser (`lib/autosave.ts`, `lib/use-autosave.ts`)

- **Timing:** saves 800 ms after the last change, one save in flight at a time; text typed meanwhile goes next with the new rev.
- **Status line:** "Saving…" → "Saved"; "Offline — will save when reconnected" retries with backoff, and at once on the browser's `online` event.
- **`412`:** a bar says "This idea was changed in another tab", with **Load latest** (take the other tab's text) or **Keep mine** (save over it). Nothing is saved until you choose.
- **`409` / `404`:** saving stops, with the reason and a Reload button.
- **`400`:** the error is shown and the next change tries again.
- **`5xx`:** retried with backoff.
- **Leaving the page:** a hidden tab saves at once; leaving with unsaved text shows the browser's "Leave site?" warning.
- **Development double mount:** React mounts components twice in development, so the queue resumes after being disposed.
- **Pasted text over the limit** is cut to the limit, with a note saying so. Counters count characters like the API.

## Project page: real 404

`/projects/{unknown or someone else's id}` now answers HTTP **404**; before, it streamed a `200` with not-found content (QA leftover K1).
- The page reads the project and its idea before anything streams (no Suspense boundary).
- It sets `export const instant = false`, the documented way to allow a blocking route under Cache Components.
- A signed-out visitor gets a real redirect for the same reason.
