# F3.5 — Storyboard version history + restore

**Status:** design **approved 2026-10-21** ([answers](#your-answers-2026-10-21)): **restore moves the pointer back (no copy)**, newest 30 kept, read-only preview, settings follow the restored version's language / length, not counted. Being built. Where the sections below still describe a copy, [Restore as a pointer](#restore-as-a-pointer-your-answer) replaces them.

**Sources:** PRD F3-FR8 (version history dropdown: versions with timestamp and change summary, "Restore this version", P1), §10 S5 (the Storyboard Review screen has version history), F7-FR4 / §8.3 (older versions are restored from history; "You can restore it from history" after a regenerate); API Design §13.4 (`GET …/storyboard/versions`, `GET …/versions/{version}`, `POST …/versions/{version}/restore` → `201`, a new version copied, `source: restore`); DB Design §4.6 (versions immutable; newest 30 kept, never the current one), §6.3, §6.4; Stitch screen 10 (the "Version 3 ▾" chip); built on F3.1–F3.4 (versions from generate, regenerate, caption edits; the review screen; the `KEEP_VERSIONS = 30` pruning).

## What you'll see

1. The **`Version N` chip** on the Storyboard step becomes a menu button (`Version 5 ▾`, as Stitch 10).
2. It opens the **history**, newest first, each row with:
   - `v5` and **current** on the one in use;
   - what made it: *Generated*, *Regenerated*, *Edited the caption*, *Rewrote the caption with AI*, *Restored version 2*, *Copied from another video*;
   - when ("12 min ago", the exact date and time on hover);
   - **View**.
3. **View** shows that version **read-only in place** (Q3): the same review screen (chips, scene cards with previews, caption), with a banner *"Viewing version 2 (Generated, 21 Oct, 14:05). This isn't the current storyboard."* and two buttons: **Restore this version** and **Back to current**. Nothing can be edited while viewing.
4. **Restore this version** (confirm: *"Make version 2 the current storyboard? Your current one stays in history as version 5."*) saves it as the **newest version** (Q1) and shows it as current: `Version 6 · Restored version 2`.
5. With only one version, the menu says "This is the first version. Edits and regenerates will appear here."

## API (already in API Design §13.4)

- **`GET /api/v1/projects/{id}/storyboard/versions?limit&cursor`** → `200 { items: [{ version, source, changeSummary, createdAt, isCurrent }], nextCursor }`, newest first, `limit` 1–50 (default 30), cursor pagination like the Library.
- **`GET /api/v1/projects/{id}/storyboard/versions/{version}`** → `200 StoryboardVersion` (the full storyboard), `404` for a pruned or unknown version.
- **`POST /api/v1/projects/{id}/storyboard/versions/{version}/restore`** with `If-Match: "<currentStoryboardVersion>"` (required) → `201 { version, project }`:
  - one transaction (DB §6.3): a new version `current + 1` with the restored version's `data` (scenes, caption, hashtags, cover text, title, hook), `source: "restore"`, `basedOnVersion` = the current one, `changeSummary: "Restored version 2"`, `changedSceneIds` = the scenes that differ from the current version (for the incremental build later), its validation report copied; the project's `currentStoryboardVersion` moves;
  - restoring the current version → `409 INVALID_STATE` ("already the current version");
  - `412` when the storyboard moved on meanwhile (the page reloads it, with the stale-tab line), `409` outside `storyboard_ready` (generating; later building), `404` unknown or pruned version / someone else's video;
  - the newest 30 are kept, as now: a restore can prune the oldest (never the current one or the one being restored, which is copied first).
- **No AI and no limit** (Q5): restoring is a copy.
- Later (M4): on `preview_ready` / `exported` a restore will also start an incremental build (API §13.4); not in this feature.

## Language and length

A version keeps the language and length it was written for (`data.language`, `data.targetDurationSec`). If the video's settings changed since (Q4), the history row shows it (`हिंदी · ~90s`) and the restore confirm says *"Version 2 is in Hindi, ~90 s. Restoring it also sets the video to Hindi, ~90 s."*; the restore then updates the project's `language` / `lengthPreset` in the same transaction, so the storyboard and its settings agree (a storyboard in Hindi with the setting on English would build the wrong voice).

## What restore doesn't touch

- **The brief** (idea session): unchanged; it only feeds the next regenerate (as in F3.1).
- **Voice, captions toggle, theme, audience, board**: unchanged (not part of a storyboard).
- **Usage counters, `ai_calls`**: nothing counted.

## The page

- `components/version-history.tsx`: the menu (a button with `aria-expanded` opening a popover with a plain list of rows and buttons; Esc closes it and returns focus to the chip), loading the list when opened (`GET …/versions`), then **View** loads that version (`GET …/versions/{v}`) and the review screen renders it read-only.
- The review screen gains a `readOnly` mode: no Edit / Rewrite in the Instagram panel, no Regenerate links; previews still play.
- After a restore, the page shows the new current version at once (like a caption save), and the menu's list refreshes next time it opens.
- Phone (360 px): the menu is a full-width sheet under the chips; rows wrap.

## Restore as a pointer (your answer)

- **`POST …/versions/{v}/restore`** with `If-Match: "<current>"` → `200 { version, project }`: one transaction sets the project's `currentStoryboardVersion` to `v` (and `language` / `lengthPreset` to the version's, when they differ), `rev` + 1. No version is inserted, nothing pruned. `409` for the current version or outside `storyboard_ready`, `412` when the current version moved on (stale tab), `404` unknown / pruned version or someone else's video.
- **The history** marks the current version; versions **newer** than it stay listed (marked "newer") and can be restored too ("forward"), so moving back and forth costs nothing.
- **The next change** made on a restored version (a caption edit, a caption rewrite saved, a regenerate) becomes version **highest + 1**, with `basedOnVersion` = the restored one, exactly as today (F3.1 and F3.4 already number new versions from the highest stored one, not from the current one). Its summary is unchanged ("Edited the caption", "Regenerated from the brief").
- **Pruning** to the newest 30 runs only when a new version is created, and never deletes the current version even when it's old (an explicit guard, tested).
- **Concurrency:** restore needs the current version number (`If-Match`); a caption save made on the old pointer gets `412` after another tab restored, and the stale-tab line shows.
- **The page** keeps the version it shows in step with the project's pointer (not "the highest number wins"), so a restore to an older version is shown at once.
